# Аккаунты учеников и сохранение результатов

Бэкенд работает на Google Apps Script и Google Таблице. Это тот же скрипт,
который уже обслуживает тренажёр ЕГЭ. Отдельный сервер не нужен.

## Что появится в таблице

**`Лист1`** — результаты (как раньше), плюс колонка `accountId`:

```
timestamp, accountId, studentName, className, lesson, variant, score, maxScore, grade, workType
```

Если колонки `accountId` ещё нет, `setup()` добавит её справа.
Порядок остальных колонок не меняется.

**`Аккаунты`** — новый лист:

```
id, name, className, track, loginKey, salt, passwordHash, createdAt, updatedAt
```

- `track`: `standard` или `ege`;
- `salt` — случайная соль;
- `passwordHash` — `SHA-256(соль + пароль)`. Сам пароль не хранится;
- `loginKey` — нормализованные «имя|класс» для поиска аккаунта.

## Установка

1. Откройте Apps Script, привязанный к вашей таблице (тот, что уже отдаёт
   URL `AKfycbydy...` для тренажёра).
2. Замените содержимое `Code.gs` на файл [Code.gs](Code.gs) из этого репозитория.
3. Сохраните проект.
4. В редакторе выберите функцию `setup` и нажмите **Выполнить**.
   Подтвердите доступ к таблице. В журнале появится сообщение об успехе.
5. Разверните новую версию:
   **Развернуть → Управление развёртываниями → изменить текущее →**
   **Версия: новая версия → Развернуть**.
6. URL `/exec` должен остаться прежним. Если Apps Script выдал новый URL,
   поменяйте его в `shared/account.js` (`DEFAULT_API_URL`).
7. В окне управления развёртыванием проверьте настройки:
   - **Выполнять от имени:** «От моего имени» (**Me**). Если выбрать
     «От имени пользователя, открывшего веб-приложение», у скрипта не будет
     прав на запись в таблицу;
   - **У кого есть доступ:** «Все» (**Anyone**). Иначе ученики не смогут
     войти и отправить результат.
8. Убедитесь, что аккаунт, от имени которого выполняется скрипт, добавлен
   в таблицу с правами **Редактор**, а не «Просмотр».

> Если запись падает с ошибкой
> «У вас нет разрешения на доступ к этому документу», почти всегда причина
> в шагах 7–8: скрипт выполняется от имени ученика или у владельца скрипта
> нет прав редактора на таблицу. Чтение при этом может работать.

> Без шагов 2–5 фронтенд будет готов, но регистрация и вход работать не будут:
> старый скрипт не знает действий `register`, `login`, `saveResult`, `myResults`.

## Проверка после деплоя

Подставьте свой URL и выполните по очереди.

Регистрация:

```bash
curl -sS -L -X POST "https://script.google.com/macros/s/ВАШ_ID/exec" \
  -H "Content-Type: text/plain;charset=utf-8" \
  -d '{"action":"register","name":"Тестов Тест","className":"11 класс","track":"ege","password":"secret123"}'
```

Повторная регистрация должна вернуть `ACCOUNT_EXISTS`.

Вход:

```bash
curl -sS -L -X POST "https://script.google.com/macros/s/ВАШ_ID/exec" \
  -H "Content-Type: text/plain;charset=utf-8" \
  -d '{"action":"login","name":"Тестов Тест","className":"11 класс","password":"secret123"}'
```

Из ответа возьмите `token` и сохраните результат:

```bash
curl -sS -L -X POST "https://script.google.com/macros/s/ВАШ_ID/exec" \
  -H "Content-Type: text/plain;charset=utf-8" \
  -d '{"action":"saveResult","token":"ВАШ_ТОКЕН","result":{"lesson":"Тренажер Сети","variant":"Trainer L1","score":9,"maxScore":10,"grade":5,"workType":"trainer-level"}}'
```

История:

```bash
curl -sS -L -X POST "https://script.google.com/macros/s/ВАШ_ID/exec" \
  -H "Content-Type: text/plain;charset=utf-8" \
  -d '{"action":"myResults","token":"ВАШ_ТОКЕН"}'
```

Неверный пароль должен вернуть `WRONG_PASSWORD`, отсутствующий аккаунт —
`NO_ACCOUNT`, просроченный или испорченный токен — `TOKEN_EXPIRED` /
`AUTH_REQUIRED`.

## Восстановление пароля

Ученик забыл пароль — учитель запускает функцию из редактора Apps Script:

```js
resetStudentPassword('Иванов Иван', '10 класс', 'новыйпароль')
```

Пароль должен быть не короче 6 символов. Функция меняет соль и хеш,
старые сессии продолжают работать до истечения токена (30 дней).
Если нужно завершить все сессии сразу, смените секрет токена:
удалите свойство `ACCOUNT_TOKEN_SECRET` в **Настройки проекта → Свойства
скрипта** и снова запустите `setup()`.

Посмотреть список аккаунтов:

```js
listAccounts()
```

## Старые результаты

Строки, созданные до появления аккаунтов, не имеют `accountId`.
Они автоматически подтягиваются в историю ученика по совпадению
`studentName + className` (без учёта регистра и лишних пробелов).

## Ограничения безопасности

- Пароли хешируются с солью, но это учебный уровень защиты, а не банковский.
- URL веб-приложения публичный. Кто знает URL, может отправлять запросы.
  Запись результатов защищена токеном, но регистрация открыта.
- Токен живёт 30 дней и хранится в `localStorage` браузера.
- Для полноценной защиты нужен обычный сервер с HTTPS и базой данных.
