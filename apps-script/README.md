# Аккаунты учеников и сохранение результатов

Бэкенд работает на Google Apps Script и Google Таблице. Это тот же скрипт,
который уже обслуживает тренажёр ЕГЭ. Отдельный сервер не нужен.

## Что появится в таблице

**`Лист1`** — результаты (как раньше), плюс колонка `accountId`:

```
timestamp, accountId, studentName, className, lesson, variant, score, maxScore, grade, workType
```

Если колонки `accountId` ещё нет, `setup()` добавит её справа.
Порядок остальных колонок не меняется.

**`Аккаунты`** — новый лист:

```
id, name, className, track, loginKey, salt, passwordHash, createdAt, updatedAt, role, scope
```

- `track`: `standard` или `ege`;
- `salt` — случайная соль;
- `passwordHash` — `SHA-256(соль + пароль)`. Сам пароль не хранится;
- `loginKey` — нормализованные «имя|класс» для поиска аккаунта
  (при смене подкласса пересчитывается автоматически);
- `className` — базовый класс (`5 класс`) или подкласс (`5а`, `5б`);
- `role` — `student`, `teacher`, `parent` или `admin`. Пустые ячейки
  считаются `student` (так автоматически обновляются старые аккаунты);
- `scope` — права доступа:
  - для `teacher` — классы через `;`, например `5 класс;6 класс`.
    Класс `5 класс` покрывает все подклассы `5а`, `5б` и т.д.;
  - для `parent` — ключи детей через `;`, например `иванов иван|5 класс`.
    При смене подкласса ребёнка ключ обновляется автоматически;
  - для `student` и `admin` — не используется.

Колонки `role` и `scope` добавляются автоматически при повторном запуске
`setup()` — существующие строки не повреждаются.

## Установка

1. Откройте Apps Script, привязанный к вашей таблице (тот, что уже отдаёт
   URL `AKfycbydy...` для тренажёра).
2. Замените содержимое `Code.gs` на файл [Code.gs](Code.gs) из этого репозитория.
3. Сохраните проект.
4. В редакторе выберите функцию `setup` и нажмите **Выполнить**.
   Подтвердите доступ к таблице. В журнале появится сообщение об успехе.
5. Разверните новую версию:
   **Развернуть → Управление развёртываниями → изменить текущее →**
   **Версия: новая версия → Развернуть**.
6. URL `/exec` должен остаться прежним. Если Apps Script выдал новый URL,
   поменяйте его в `shared/account.js` (`DEFAULT_API_URL`).
7. В окне управления развёртыванием проверьте настройки:
   - **Выполнять от имени:** «От моего имени» (**Me**). Если выбрать
     «От имени пользователя, открывшего веб-приложение», у скрипта не будет
     прав на запись в таблицу;
   - **У кого есть доступ:** «Все» (**Anyone**). Иначе ученики не смогут
     войти и отправить результат.
8. Убедитесь, что аккаунт, от имени которого выполняется скрипт, добавлен
   в таблицу с правами **Редактор**, а не «Просмотр».

> Если запись падает с ошибкой
> «У вас нет разрешения на доступ к этому документу», почти всегда причина
> в шагах 7–8: скрипт выполняется от имени ученика или у владельца скрипта
> нет прав редактора на таблицу. Чтение при этом может работать.

> Без шагов 2–5 фронтенд будет готов, но вход и сохранение результатов работать не будут:
> старый скрипт не знает действий `login`, `saveResult`, `myResults`,
> `viewResults`, `admin*`, `setStudentClass`, `createStudentAccount`,
> `adminUpdateAccount`.
>
> Текущая версия скрипта — `2026-11-23-teacher-create-v1`. После деплоя откройте
> URL `/exec` в браузере: в ответе должна быть эта версия.

## Роли и права

| Роль | Кто создаёт | Что видит |
|------|-------------|-----------|
| `student` (ученик) | учитель или администратор | только свои результаты |
| `teacher` (учитель) | администратор | результаты классов из своего `scope` |
| `parent` (родитель) | администратор | результаты детей из своего `scope` |
| `admin` (администратор) | администратор | все аккаунты и все результаты |

Публичная самостоятельная регистрация отключена: действие `register` возвращает
`REGISTRATION_DISABLED`. Аккаунты учеников создаёт учитель (в пределах своего
`scope`) или администратор через `createStudentAccount`; сервер сам генерирует
пароль и возвращает его один раз для печати/раздачи. Привилегированные аккаунты
создаёт администратор в своей панели (`admin.html`) через `adminCreateAccount`.

Роль хранится в таблице и возвращается сервером при входе. Значение в
`localStorage` используется только для выбора нужной страницы после входа;
все серверные действия заново проверяют роль по записи в таблице.

### Вход под служебной ролью

В форме входа в списке «Класс» есть пункты «Учитель», «Родитель» и
«Администратор». Выберите нужный пункт и введите имя и пароль аккаунта,
созданного администратором. Указывать реальный класс (например, «11 класс»)
не нужно: сервер найдёт аккаунт по имени и роли, даже если в таблице в колонке
`className` у него записан обычный класс. Принимаются и старые значения списка
«Учителя», «Родители», «Администрация».

Обычные ученики по-прежнему входят, выбирая свой класс (5–11). При
неоднозначности (несколько аккаунтов с одним именем и ролью) вход вернёт ошибку.

### Первый администратор

Публичная регистрация отключена, поэтому сначала нужно вручную создать
обычный аккаунт. После обновления `Code.gs` и повторного запуска `setup()`
вызовите в редакторе Apps Script, например:

```js
createManualAccount('Иванов Иван', '10 класс', 'сложныйпароль')
makeAdmin('Иванов Иван', '10 класс')
```

Если нужный аккаунт уже есть (создан до отключения регистрации), достаточно
`makeAdmin(...)`. Войдите под ним в `login.html` (класс «Администратор»).
Дальнейшие аккаунты и роли создаются через панель администратора на сайте.

Для учеников можно создавать аккаунты прямо из кабинета учителя: откройте
`teacher.html`, укажите фамилию, имя, класс и букву, нажмите «Создать и
сгенерировать пароль». Пароль появится один раз; сразу нажмите «Печать
карточек» и раздайте карточки ученикам. В панели администратора (`admin.html`)
доступны такие же действия плюс редактирование ФИО, класса и пароля ученика.


Для ручного назначения ролей есть вспомогательные функции:

```js
setAccountRole('Иванова Мария', 'Учителя', 'teacher', '5 класс;6 класс')
makeTeacher('Иванова Мария', 'Учителя', '5 класс;6 класс')
makeParent('Иванов Иван', 'Родители', 'иванов иван|5 класс')
```

Последнего администратора снять роль нельзя — сервер вернёт `LAST_ADMIN`.

### Новые действия API

```
viewResults          { token }                                  → students, results, scope
adminListAccounts    { token }                                  → accounts
adminCreateAccount   { token, name, className, password, role, scope }
adminSetRole         { token, accountId, role, scope }
adminResetPassword   { token, accountId, newPassword }
setStudentClass      { token, accountId, className }            → account
createStudentAccount { token, name, className }                 → created[], errors[]
                     { token, students: [{name, className}] }   (роль teacher/admin)
adminUpdateAccount   { token, accountId, name?, className?,     → account, credentials?
                       newPassword?, generatePassword? }         (только admin, только student)
```

`createStudentAccount` создаёт учеников с серверно-сгенерированным паролем.
Пароль возвращается **один раз** в `credentials.password` — после закрытия
страницы восстановить его нельзя, только сбросить. Учитель может создавать
аккаунты только в классах из своего `scope`.

`adminUpdateAccount` позволяет администратору изменить ФИО, класс и/или пароль
ученика. При смене ФИО/класса обновляются `loginKey` ученика и ключи ребёнка в
`scope` родителей; исторические строки попыток не переписываются.

`viewResults` доступен ролям `teacher`, `parent` и `admin`. Учитель получит
только строки своих классов, родитель — только привязанных детей. Ответы
содержат сводку по каждому ученику (средний процент, лучший результат по теме)
и последние работы. `adminListAccounts` не возвращает соли и хеши паролей.

### Подклассы (буквы)

Вместо одного «5 класс» можно использовать `5а`, `5б`, `5в`, `5г`. Буква
выбирается при регистрации, создании аккаунта администратором и меняется
в панелях `teacher.html` и `admin.html` через `setStudentClass`.

- `setStudentClass` доступен ролям `teacher` и `admin`. Ученик и родитель
  получить доступ не могут.
- Учитель может менять подкласс только ученикам, у которых и старый, и новый
  классы попадают в его `scope`. Для `5 класс` это `5а`, `5б` и т.д.
- Менять можно только роль `student`; при попытке изменить учителя сервер
  вернёт `FORBIDDEN`.
- `className` нормализуется: `5 а`, `5-а`, `5А` → `5а`. Некорректные значения
  отклоняются с `BAD_REQUEST`, занятые «имя|класс» — с `ACCOUNT_EXISTS`.
- Каталог уроков и экзаменов по-прежнему привязан к базовому классу:
  ученик `5а` видит материалы `5 класс`.
- В отчётах для строк с привязанным аккаунтом используется текущий класс
  ученика, поэтому вся история остаётся в одном подклассе. Старые строки
  без `accountId` сопоставляются по имени и базовому классу.
- При смене подкласса обновляются `loginKey` ученика и ключи ребёнка в `scope`
  родителей. Старые строки результатов не перезаписываются.

## Проверка после деплоя

Подставьте свой URL и выполните по очереди.

Регистрация:

```bash
curl -sS -L -X POST "https://script.google.com/macros/s/ВАШ_ID/exec" \
  -H "Content-Type: text/plain;charset=utf-8" \
  -d '{"action":"register","name":"Тестов Тест","className":"11 класс","track":"ege","password":"secret123"}'
```

Повторная регистрация должна вернуть `ACCOUNT_EXISTS`.

Вход:

```bash
curl -sS -L -X POST "https://script.google.com/macros/s/ВАШ_ID/exec" \
  -H "Content-Type: text/plain;charset=utf-8" \
  -d '{"action":"login","name":"Тестов Тест","className":"11 класс","password":"secret123"}'
```

Из ответа возьмите `token` и сохраните результат:

```bash
curl -sS -L -X POST "https://script.google.com/macros/s/ВАШ_ID/exec" \
  -H "Content-Type: text/plain;charset=utf-8" \
  -d '{"action":"saveResult","token":"ВАШ_ТОКЕН","result":{"lesson":"Тренажер Сети","variant":"Trainer L1","score":9,"maxScore":10,"grade":5,"workType":"trainer-level"}}'
```

История:

```bash
curl -sS -L -X POST "https://script.google.com/macros/s/ВАШ_ID/exec" \
  -H "Content-Type: text/plain;charset=utf-8" \
  -d '{"action":"myResults","token":"ВАШ_ТОКЕН"}'
```

Неверный пароль должен вернуть `WRONG_PASSWORD`, отсутствующий аккаунт —
`NO_ACCOUNT`, просроченный или испорченный токен — `TOKEN_EXPIRED` /
`AUTH_REQUIRED`.

## Восстановление пароля

Ученик забыл пароль — учитель запускает функцию из редактора Apps Script:

```js
resetStudentPassword('Иванов Иван', '10 класс', 'новыйпароль')
```

Пароль должен быть не короче 6 символов. Функция меняет соль и хеш,
старые сессии продолжают работать до истечения токена (30 дней).
Если нужно завершить все сессии сразу, смените секрет токена:
удалите свойство `ACCOUNT_TOKEN_SECRET` в **Настройки проекта → Свойства
скрипта** и снова запустите `setup()`.

Посмотреть список аккаунтов:

```js
listAccounts()
```

## Старые результаты

Строки, созданные до появления аккаунтов, не имеют `accountId`.
Они автоматически подтягиваются в историю ученика по совпадению
`studentName + className` (без учёта регистра и лишних пробелов). Если ученик
позже перешёл с «5 класс» на «5а», строки «5 класс» тоже считаются его
историей — сравнение идёт по базовому классу.

## Ограничения безопасности

- Пароли хешируются с солью, но это учебный уровень защиты, а не банковский.
- URL веб-приложения публичный. Кто знает URL, может отправлять запросы.
  Запись результатов защищена токеном, но регистрация открыта (только для
  роли `student`). Роли `teacher`, `parent` и `admin` выдаёт администратор,
  их нельзя получить через публичную регистрацию.
- Проверка прав на чтение чужих результатов выполняется сервером: подмена
  роли в `localStorage` не даёт доступа к данным других аккаунтов.
- Токен живёт 30 дней и хранится в `localStorage` браузера.
- Для полноценной защиты нужен обычный сервер с HTTPS и базой данных.
